# V3-08 - Formal Assurance (Gate I & II), AssuranceCase Reports & Optimization

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Requirements

1. **AssuranceCase Reports & Search Bounds (`S19`, `OPR-FULL-026`, `FULL-ACC-026`)**:
   - An AssuranceCase explicitly states fragment, hypotheses, tool versions, search bounds, and outcomes (`PROVEN_IN_MODEL`, `COUNTEREXAMPLE`, `BOUNDED_NO_COUNTEREXAMPLE`, `INCONCLUSIVE`, `TIMEOUT`, `UNSUPPORTED`).
   - Finite search depth K produces `BOUNDED_NO_COUNTEREXAMPLE` and cannot be misrepresented as unbounded mathematical proof (`FULL-ACC-026`).
2. **Differential Equivalence & Counterexample Fixtures (`S19`, `OPR-FULL-027`, `FULL-ACC-027`)**:
   - Differential execution between reference interpreter and backend runtime detects semantic divergence.
   - Any divergence blocks publication and generates a reproducible counterexample test fixture (`FULL-ACC-027`).
3. **Scenario Isolation & Zero-Side-Effect Sandbox (`S19`, `OPR-FULL-028`, `FULL-ACC-028`)**:
   - Formal simulation scenarios execute under strict containment: only simulator endpoints receive effects, and real credentials remain completely unavailable (`FULL-ACC-028`).
4. **Inconclusive Evidence Rejection (`S19`, `OPR-FULL-029`, `FULL-ACC-029`)**:
   - Inconclusive results and solver timeouts are never relabeled as PASS.
   - Release profiles requiring proof reject inconclusive reports with `InconclusiveAssuranceRejectedError` (`FULL-ACC-029`).
5. **Incremental vs Full Verification Equivalence (`S19`, `OPR-FULL-030`, `FULL-ACC-030`)**:
   - Incremental evaluation across transitive dependencies must produce identical verdicts to full baseline evaluation.
   - Any inconsistency blocks the release with a counterexample (`FULL-ACC-030`).
6. **Compiler Gate I & Knowledge Admission Gate II (`S19`)**:
   - Gate I validates that permitted executions respect declared rules without over-restriction.
   - Gate II governs knowledge admission against registered evidence and policy.
