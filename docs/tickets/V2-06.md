# V2-06 - Typed Read Functions and L2 Context Verification

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Requirements

1. **Typed Read Functions (`OPR-FUN-001..003`)**:
   - Pure deterministic query functions with explicit input/output schemas, versioned logic, and caller permissions.
   - Stage edit functions: stage ontology mutations only; fail closed if aborted without leaking state; forbid direct side-effects.
   - Materialization: preserve input hash, logic version, and dependency versions. Invalidate cache when dependencies change.
2. **Six-Part Prediction Contract & Rules Precedence (`OPR-FUN-004..006`)**:
   - Model applicability envelope: inputs outside envelope report `out_of_scope` and cannot authorize actions.
   - Six explicit groups: `value`, `uncertainty`, `inputSnapshot`, `versionChain`, `scopeCheck`, and `readiness`. Missing evidence cannot be bypassed by high confidence.
   - Deterministic hard business rules strictly override model scores and explanations.
3. **L2 Context & Ground Truth Verification (`OPR-L2-001..003`)**:
   - Verify factual assertions against visible bitemporal evidence context; absent properties or mismatches are rejected.
   - Completeness checking against versioned Must-Answer templates with contraindication checks.
   - Citation resolution: verify claim span, source ID, and version against evidence text.
4. **Communication Compliance & Extraction Admission (`OPR-L2-004..006`)**:
   - Ensure communication does not exceed actor authority (e.g. `OBSERVE`-tier claiming execution).
   - Extraction vs Admission: Extracted candidate facts remain `PENDING` until explicit permitted human confirmation.
   - Quality gates integrated at runtime boundary: reject unverified outputs or route to review.
