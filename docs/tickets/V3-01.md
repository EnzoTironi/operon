# V3-01 - Contracted Inbound & Outbound Connectors

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Requirements

1. **Connector Capability Contracts (`S15`, `OPR-FULL-043`)**:
   - Each connector explicitly declares transport type, versions, supported capabilities (`supportsConditionalWrites`, `supportsIdempotencyKeys`, `supportsCompensatingActions`, `supportsAtomicBatch`, `supportsChangeDataCapture`), and source freshness.
   - When a workflow or recipe package requires a guarantee (e.g. conditional write) not provided by the connector, compatibility validation fails explicitly with `ConnectorCapabilityMismatchError` (`FULL-ACC-043`).
2. **Outbound Operations & Credential Isolation (`S15`, `OPR-FULL-044`)**:
   - Outbound connector operations declare operation identity, retryability, and compensation actions.
   - Broker boundary isolation: credentials live in the broker/worker boundary; agents cannot read or export credentials (`BrokerCredentialViolationError`).
   - Token availability does NOT mint business authority: execution without an active kernel `TaskMandate` / `IntentGrant` fails with `BusinessAuthorityMissingError`.
3. **Compensation on Partial Failure**:
   - If a multi-step outbound operation fails, registered compensating actions are executed to restore consistency without relying on an impossible distributed two-phase commit.

## Executable tests

- `FULL-ACC-043`: Given a source does not offer conditional writes; when a package demands that guarantee **Expected:** compatibility fails explicitly with structured error and is not hidden by a lossy wrapper.
- `FULL-ACC-044.T01`: Outbound connector requires business authority; valid bearer token without IntentGrant fails with `BusinessAuthorityMissingError`.
- `FULL-ACC-044.T02`: Agent attempt to inspect or extract outbound credentials fails with `BrokerCredentialViolationError`.
- `OUTBOUND-COMP-001`: Outbound operation with compensation handler triggers compensation when downstream service errors.
