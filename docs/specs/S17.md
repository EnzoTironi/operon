# Self-contained S17

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Two ledgers

Keep normative requirements/scenarios immutable by source version. Store candidate-specific observations separately. Source review, syntax checks, verifier unit tests, real application integration, deployment evidence, model evaluation and formal results are distinct classes. None substitutes for another without an explicit profile rule. Never turn NOT_RUN into PASS because the test was authored.

Every concrete case has an ID, protected expected result/oracle, required real adapter/process/transport/model, fixture identity, positive and negative controls, assertion count, applicability and completion rule. Derived cases cover threat and concurrency matrices; two prose scenarios per requirement are not necessarily two test functions.

## Evidence envelope

Bind candidate archive and executable tree, lockfile, toolchain, harness, protected catalogue, runtime configuration, policy/model/fixture identities, environment, start/finish, command, exit status, case results, artifact hashes and runner identity. Redact secrets without erasing necessary observations. Stable source lineage does not mean that prior run evidence applies to a changed binary.

The independent evaluator chooses the required profile and unresolved decisions outside the candidate workspace. Missing, duplicated, skipped, malformed, stale, wrong-candidate or untrusted evidence is rejected. Exclusions require separate reviewed profile changes; the candidate cannot shrink its own catalogue. A signed run records a trusted runner's attestation, not a mathematical proof of correctness.

## Factory

Implementer, verifier and integrator operate under separate capabilities. The implementer cannot mutate protected tests, expected outcomes, public-key trust, release rules or acceptance status. A generated PR includes bounded scope, requirements, tests, migration/recovery implications and exact observations. The verifier runs independent oracles/mutations and attacks boundary composition. Publication may be automated under independently delegated authority.

## Included reference tooling

`validation/evidence-gate.mjs` verifies Ed25519-signed run bytes and candidate/profile/catalogue/fixture/policy/artifact bindings using Node built-ins. Its 38 self-tests execute against synthetic fixtures. It returns READY_FOR_INDEPENDENT_RELEASE_REVIEW, not product certification. Trust policy, key and evaluator must be external to the candidate; a compromised trusted runner or mutable artifact directory is outside what signatures alone solve. Harden key custody, immutable publication, time source and CI isolation before release use.

## Acceptance and mutations

Drop a case; duplicate a case; report success with zero assertions; forge a runner; change tree/lock/catalogue/config; use a smoke artifact for a real-integration requirement; alter a receipt; traverse artifact paths; use a symlink; interrupt execution; resolve an unapproved decision. All must fail. Valid signed evidence with all required cases succeeds for independent review. Actual runtime tests remain blocked here until the real dependencies can be installed.

Sources: UNI/E2E/BLD; WS-13; independent acceptance pack; new VAL family and current verifier diagnostics.
