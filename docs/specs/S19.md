# Self-contained S19

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Scope
Retain the book's CROV/V-EDO agenda as explicit engineering and research work. Do not claim that a validator with the same name implements the entire proposal. A bounded transition check, a rule adjudication and a physical forecast have different meanings and evidence.

## Executable fragment
Define the supported typed states, action effects, rule priorities, missingness and invariants. Restrict the first verifiable fragment to constructs with specified semantics. Arbitrary extension code remains outside a theorem unless modeled under explicit assumptions. Security isolation cannot be proven merely by reasoning about an abstract action graph that omits host side effects.

Implement a reference interpreter first. Prolog may support explainable rule jurisdiction where selected; Z3/transition tools can search counterexamples. Compiler Gate I checks that permitted executions respect declared rules and must also consider completeness/over-restriction. A compiler that rejects everything is not semantically faithful. Gate II governs knowledge admission against evidence and policy. Neither solver discovers organizational authority by itself.

## Reports
An AssuranceCase identifies candidate, fragment, rules, hypotheses, solver/tool versions, invariant set, initial states, action domain, search bounds, result and reproducible artifacts. Outcomes include proven-in-model, counterexample, bounded-no-counterexample, inconclusive, timeout and unsupported. Never relabel the last three as PASS. Failed historical traces become independent regression cases.

## Simulation and optimization
Scenarios execute the relevant model under a pinned baseline with separately enforced containment. An optimizer may find a feasible/better schedule under declared constraints; that is not assurance that the physical model is correct. Evaluate prediction against held-out outcomes and record measurement uncertainty, coverage and invalid contexts. Candidate scenarios remain hypothetical until new production actions are authorized and confirmed.

## Acceptance
Adversarial rule sets, omitted state variables, unsafe translation, overly restrictive translation, stale cached proof, unsupported function, changed assumption, solver timeout and non-reproducible counterexample. Cross-check selected finite models by exhaustive reference enumeration. Runtime invariants still execute even when the formal result is favorable. Benchmark usefulness and cost against deterministic baselines.
