# Self-contained S06

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Three distinct objects

An `IntentRequest` is an untrusted proposed goal. A `TaskMandate` is an authorized outcome with constraints and an issuer. An `IntentGrant` is the enforceable delegation of a subset of that mandate to an actor or service. Earlier `Mandate`/`CapabilityGrant` names map to these concepts only after an explicit compatibility decision; preserved source records are not silently renamed.

A grant contains immutable purpose/version, issuer, parent, actor, tenant/environment, eligible resources/actions, data-use conditions, destination audiences, budget/expiry, delegation limits, policy references and revocation epoch. A request in prose cannot issue or expand it. The sponsor is not necessarily the executor. Child scope must be no broader than the parent on every relevant dimension; semantic subset checks are application-specific.

## Evaluation

Proposed decision algebra: ALLOW, DENY, REVIEW_REQUIRED, EVIDENCE_INSUFFICIENT; infrastructure failure is a separate typed outcome. This is a candidate mapping pending the original result-algebra decisions. Evaluate actor authority, current grant, target, purpose, input processing, effect restrictions, evidence closure, aggregate reservations and audience. An ALLOW output is not a reusable bearer credential and is revalidated at commit/delivery checkpoints.

Reading, model processing, embedding, caching, training reuse, notification, export and publication are separate uses. The destination model/tool must be authorized before private bytes are sent. Read access by a director does not authorize disclosure into a general room. Sensitive aggregates and denials require leakage-aware policies. An authorized confidential evaluator may produce a minimal denial without exposing its reasons to an unauthorized audience.

## Budgets and obligations

Enforce `committed + outstanding reservations <= authorized total` transactionally across agents, descendants, processes and retries. A token field is not a usage ledger. Unknown external outcomes retain appropriate reservations until reconciled. Grant revocation cannot undo already disclosed data or confirmed external effects; records state what can still be stopped.

Obligations include notifications, retention, evidence collection, review and follow-up. Fulfillment is observed, not self-asserted by a planner. Unknown or unmet obligations follow declared escalation semantics. Emergency stop, resumption and break-glass are separately authorized control actions, not omnipotent sentinel powers.

## Acceptance

Legitimate multi-step delegated mission succeeds without per-step human prompts. The same mission fails closed for scope expansion, split-budget evasion, revoked grants, prohibited processors and audience leakage. Test concurrency, parent/child expiry, detached workers, downstream memory, hidden veto evidence and changes after approval. Evaluate false denials and approval burden as well as unsafe allowances.

Sources: IBAC-001–030; AUTHINT/BAI; FULL autonomy and federation requirements; WS-04/06. No model-confidence threshold grants authority.

## v4.2 V0 amendment — external agents

External agents select only server-issued mandates/grants visible to their authenticated actor, sponsor, tenant and environment. CLI/MCP payloads may reference authority records but cannot create them. Noninteractive delegated work is permitted inside an active grant; purpose, resource, data use, processor, audience, budget, expiry and delegation are revalidated at prepare, commit and delivery. Generated views and MCP Apps inherit no authority beyond the invoking context.
