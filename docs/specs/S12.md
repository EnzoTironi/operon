# Self-contained S12

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Mission contract

Represent a desired outcome, issuer, owner, evaluation predicates, time horizon, scope, allowed operations, grants, evidence obligations, budgets, fallback/escalation and stop conditions. The plan can evolve while mandate constraints remain fixed. A planner cannot redefine success to close its own mission.

Plans are versioned DAGs or typed workflows with preconditions, resource requirements, candidate effects, checkpoints and expected observations. Execute through the same governed Action/Operation services as humans. An agent can choose tactics and gather missing evidence inside its grant; it cannot use direct database credentials or call unrestricted external services.

## Scheduling and delegation

Subagents have distinct identities and attenuated grants. Budgets are shared transactionally across descendants. Cancellation, revocation, ownership handover and worker failure propagate. Distinguish user-bound missions from organization-owned missions. Offboarding an initiator does not silently leave personal authority alive, nor necessarily cancel organization-owned work without the declared policy.

Evidence acquisition is a registered action: fetch an approved source, request inspection, ask a person, or run a scenario. Its cost and confidentiality are governed. Absence of data is not permission for the model to invent an operational fact.

## Models and context

Use a provider-neutral gateway with authorized processors, model/version identity, input classification, prompt/tool releases, recorded output and metering. Keep extraction, retrieval, planning and sentinel roles separate in authority. Memory adapters preserve lineage, purpose, audience and temporal validity; Graphiti is an optional adapter rather than the transactional source of truth.

Model outputs have applicability and uncertainty fields. Repeated equal outputs on a few inputs establish sampled repeatability only. Formal determinism, causal prediction and physical simulation require distinct models/evidence. Outage or a changed provider produces a recorded lifecycle event and an explicit fallback policy.

## Outcome evaluator

Independent trusted observations determine success, partial completion or failure. The evaluator cannot be replaced by the planner through ordinary code tools. A sent request is not delivery; a proposed fix is not verified effectiveness. Missions may remain blocked or inconclusive when observations are unavailable.

## Acceptance and product value

Run benign/adversarial multi-step missions, branching plans, partial effects, denial, re-planning, model outage, prompt injection, data-processing restrictions and distributed budget races. Measure actual outcome completion, human interventions, total spend, latency, false denial and incident recovery. A system that always blocks work is not successful autonomy.
