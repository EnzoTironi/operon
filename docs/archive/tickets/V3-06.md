# V3-06 - Tenant Resource Quotas, Operational Economics & Sovereign Locality

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Requirements

1. **Multi-Tenant Quota & Contention Protection (`S16`, `OPR-FULL-048`, `FULL-ACC-048`)**:
   - Each tenant has declared resource quotas: concurrency limit, rate limit, and transactional token/spend budget.
   - Guaranteed capacity reservation protects tenants against noisy-neighbor starvation: when tenant A sends burst traffic exceeding quota, tenant A is rate-limited / throttled while tenant B's guaranteed capacity is strictly preserved.
   - Bounded missions require finite aggregate resource budgets: requests exceeding limits fail with structured `TenantQuotaExceededError`.
2. **Sovereign Locality & Egress Enforcement (`S16`, `OPR-FULL-050`, `FULL-ACC-050`)**:
   - Locality policies restrict model routing, log export, backup transfer, and artifact distribution to declared authorized regions.
   - Any attempt to route model calls or export logs/backups outside permitted boundaries is blocked _before_ data transmission with `RegionalLocalityViolationError`.
3. **Contention & Usage Accounting (`S16`)**:
   - Contention reports distinguish passive billing counters from active transactional mission bounds.
   - Metered metrics track active tasks, queue contention, throttled counts, and confirmed guaranteed capacity.
