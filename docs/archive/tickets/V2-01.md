# V2-01 - Authority Tiers and Bounded Autonomy

## Program frame (normative in this document)

Operon is a zero-permanent-UI, agent-agnostic operating kernel. One kernel owns versioned contracts, identity and authority, canonical state, proposals, execution receipts, evidence and the result algebra. CLI, MCP, SDK, generated application surfaces, recipes and enterprise modules are adapters over that kernel and may not reimplement its rules.

Release order is V0 -> V1 -> V2 -> V3. V0 proves external-agent authoring, ingestion, reconciliation and safe action. V1 proves Action Inbox, exact approval, durable execution and honest outcomes. V2 adds post-V0 missions, disposable generated surfaces and the recipes/skills/module ecosystem. V3 adds federation, factory, sovereign operations and formal assurance. A later release cannot be claimed before the preceding gate passes on the same pinned candidate with independent evidence.

Current status is `SPEC_CONSISTENT_NOT_PRODUCT_PASS`: no runtime case has been executed by this dossier.

## Requirements

1. **Four Authority Tiers & Interaction Modes**:
   - `Tier 1 (Observe)`: Pure read/query operations only. Any write or proposal request is rejected with `TierAuthorityExceededError`.
   - `Tier 2 (Propose)`: Agent can query and create `ActionProposal` instances routed to human Action Inbox. Cannot self-approve or execute. Human executes or approves.
   - `Tier 3 (Execute with Approval)`: Agent can propose and execute, but execution strictly requires a valid, unconsumed human `ApprovalReceipt` bound by hash to the exact proposal.
   - `Tier 4 (Bounded Autonomy)`: Agent can execute directly without human approval IF AND ONLY IF the action matches the authorized action classes, target object set, maximum risk band (`LOW`, `MEDIUM`, `HIGH`), and within remaining budget.
2. **TaskMandate Authority Envelope**:
   - Explicit `allowedActionClasses: readonly string[]`
   - Target `objectSet: readonly string[]` (or wildcard `"*"`)
   - Maximum `riskBand: "LOW" | "MEDIUM" | "HIGH"`
   - `budgetLimit`: max invocations or spend
3. **Earned Promotion & Demotion**:
   - Promotion to Tier 4 requires calibration evidence (shadow trial pass rate >= threshold, zero safety violations). Unjustified promotion without evidence is rejected.
   - Deterioration triggers (e.g. consecutive failed actions, safety policy violation, manual safety tripwire) immediately demote the agent to a lower tier (Tier 2 or Tier 1) and record an auditable demotion event.
4. **Auditable Actor Separation**:
   - Distinct actor/confirmation records in execution receipts for Tier 2 human execution, Tier 3 approved agent execution, and Tier 4 autonomous execution.

## Executable tests

- `AGT-001.T01`: Exercise every tier against read, propose, approve, execute, and administer operations.
- `AGT-001.T02`: Complete the same business action under tiers 2 and 3; verify distinct actor/confirmation records.
- `AGT-002.T01`: Try an allowed action outside the object set/risk band, and an unlisted action inside it; verify out-of-envelope rejection.
- `AGT-002.T02`: Promote without required reports, then simulate a declared deterioration trigger; verify unjustified promotion blocks and demotion reduces future authority and is audited.
